    Mengenal Laravel¶

    Pada bab utama sebelumnya kamu membangun Sistem Manajemen Siswa dengan PHP native: kamu menulis sendiri pengaturan route, pembacaan form, validasi, escape keluaran, dan penyimpanan data. Hasilnya berjalan, tetapi banyak bagian yang terasa berulang dan harus dijaga sendiri (termasuk keamanan). Laravel hadir untuk mengambil alih sebagian besar pekerjaan berulang itu agar kamu bisa fokus pada fitur aplikasi.

    Tujuan Pembelajaran¶

    Setelah menyelesaikan sub bab ini, kamu dapat:

    • Menjelaskan apa itu framework dan apa itu Laravel.
    • Menyebutkan fitur utama Laravel dan memetakannya ke pekerjaan yang dulu kamu tulis manual.
    • Menjelaskan dua cara memakai Laravel: full stack framework dan API backend.
    • Membaca tabel versi dan dukungan Laravel serta menjelaskan versi yang dipakai di materi ini.
    • Memeriksa apakah PHP di komputermu memenuhi syarat Laravel 13.x.
    • Menemukan informasi yang tepat di dokumentasi resmi Laravel.

    Prasyarat¶

    • Bab utama Dasar Web dan PHP, terutama Proyek Sistem Manajemen Siswa, Class dan Objek, dan Composer dan Manajemen Paket.
    • PHP dan Composer terpasang (php -v dan composer -V berfungsi).
    • Browser dan koneksi internet untuk membuka dokumentasi.

    Sub bab ini belum memasang Laravel; pemasangan dikerjakan pada sub bab Memasang Laravel.

    Pengantar¶

    Pikirkan kembali proyek siswa. Untuk satu halaman "Tambah Siswa" kamu mengerjakan:

    1. Memetakan alamat URL ke berkas PHP.
    2. Membaca dan membersihkan input form.
    3. Memvalidasi isian dan menampilkan pesan error.
    4. Meng-escape semua keluaran agar aman dari XSS.
    5. Menyimpan data (di berkas JSON).
    6. Mengalihkan pengguna setelah berhasil.
    7. Menyusun tampilan HTML yang konsisten.

    Jika aplikasimu memiliki lima puluh halaman, pekerjaan itu dikalikan lima puluh, dan setiap kali ada yang terlewat (misalnya lupa melindungi form dari CSRF) muncul celah keamanan. Pertanyaan yang wajar: adakah cara yang sudah teruji untuk melakukan pekerjaan umum ini? Jawabannya adalah framework.

    Penjelasan Konsep¶

    Apa itu framework?¶

    Framework adalah kerangka kerja berisi struktur, aturan, dan kumpulan alat siap pakai untuk membangun aplikasi. Kamu menulis bagian yang khas untuk aplikasimu; framework mengerjakan bagian yang umum.

    Analogi

    Membangun aplikasi tanpa framework seperti membangun rumah dengan membuat sendiri batu bata, pipa, dan kabel. Memakai framework seperti memakai bahan bangunan standar dan denah yang sudah teruji: kamu tetap mendesain rumahmu, tetapi tidak membuat ulang batu bata.

    Dua ciri penting framework:

    • Struktur tetap: ada tempat yang jelas untuk setiap jenis kode (route, controller, tampilan).
    • Alat bawaan: validasi, akses database, keamanan, pengiriman email, dan lainnya sudah disediakan.

    Apa itu Laravel?¶

    Menurut dokumentasi resminya, Laravel adalah web application framework dengan sintaks yang ekspresif dan elegan. Laravel ditulis dengan PHP, bersifat open source (kodenya terbuka di GitHub), dan dirancang agar pengalaman pengembang menyenangkan sambil tetap menyediakan fitur yang kuat seperti dependency injection, lapisan abstraksi database yang ekspresif, antrean dan pekerjaan terjadwal, serta pengujian unit dan integrasi.

    Laravel memanggil dirinya framework yang progresif: ia tumbuh bersamamu. Pemula bisa memulai dengan fitur dasar, sedangkan pengembang berpengalaman mendapat alat tingkat lanjut.

    Dua cara memakai Laravel¶

    Dokumentasi resmi menyebut dua pola utama:

    Pola Artinya Contoh
    Full stack framework Laravel menerima request dan membuat tampilan (Blade, atau hibrida seperti Inertia) Sistem informasi akademik dengan halaman web
    API backend Laravel menyediakan data dan autentikasi untuk aplikasi lain lewat API Backend untuk aplikasi mobile atau frontend JavaScript terpisah

    Dokumentasi menyebut pola pertama sebagai cara yang paling umum dan produktif, dan itu juga yang kita mulai lebih dulu. Pola API dipelajari pada bab utama REST API.

    Ekosistem¶

    Di sekitar framework inti ada alat pendukung. Berikut yang disebut dalam dokumentasi resmi (kamu tidak perlu menguasainya sekarang):

    Alat Fungsi singkat
    Artisan Alat baris perintah bawaan untuk membuat kode dan menjalankan tugas
    Starter kits Kerangka aplikasi siap pakai dengan autentikasi
    Laravel Herd Lingkungan pengembangan Laravel dan PHP untuk macOS dan Windows
    Vite Alat untuk mengompilasi CSS dan JavaScript
    Laravel Sanctum Autentikasi sederhana untuk API, SPA, dan aplikasi mobile
    Livewire dan Inertia Paket komunitas untuk antarmuka interaktif tanpa meninggalkan Laravel
    Laravel Cloud dan Forge Layanan untuk men-deploy aplikasi

    Versi dan dukungan¶

    Laravel dirilis setahun sekali. Setiap rilis mendapat perbaikan bug selama 18 bulan dan perbaikan keamanan selama 2 tahun. Berikut data dari halaman rilis resmi:

    Versi PHP yang didukung Rilis Perbaikan bug sampai Perbaikan keamanan sampai
    12 8.2 - 8.5 24 Februari 2025 13 Agustus 2026 24 Februari 2027
    13 8.3 - 8.5 17 Maret 2026 Q3 2027 17 Maret 2028

    Materi ini memakai Laravel 13.x, yang membutuhkan PHP 8.3 atau lebih baru.

    Perhatikan versi dokumentasi

    Cara menulis sesuatu dapat berubah antar versi. Selalu pastikan halaman dokumentasi yang kamu buka bertuliskan 13.x. Banyak tutorial di internet masih menulis kode untuk versi lama.

    Kelebihan dan batasan¶

    Kelebihan Batasan
    Menghemat pekerjaan berulang dan mengurangi bug umum Ada kurva belajar: istilah dan konvensi baru
    Struktur konsisten, mudah dipahami tim Perlu memahami PHP dan OOP dengan baik
    Fitur keamanan bawaan Framework menambah lapisan; aplikasi sangat kecil mungkin terasa berlebihan
    Dokumentasi dan komunitas besar Perlu mengikuti perubahan antar versi

    Laravel bukan satu-satunya pilihan; framework PHP lain (misalnya Symfony) atau PHP native juga dipakai sesuai kebutuhan. Perbandingan dengan PHP native dibahas pada sub bab Laravel dibanding PHP Native.

    Cara Kerja¶

    Gambaran sangat sederhana tentang perjalanan sebuah request di aplikasi Laravel:

    flowchart LR
    B[Browser] --> W[Web server]
    W --> I["public/index.php<br/>(pintu masuk)"]
    I --> L[Laravel]
    L --> R[Routing]
    R --> C[Controller]
    C --> M[(Database lewat Eloquent)]
    C --> V["View (Blade)"]
    V --> B

    Semua request masuk lewat satu pintu, public/index.php. Dari sana Laravel mencocokkan URL dengan route, menjalankan controller, mengambil data, lalu mengembalikan tampilan. Diagram ini disederhanakan; urutan lengkapnya dibahas pada sub bab Request Lifecycle.

    Contoh Praktik¶

    Berikut perbandingan satu pekerjaan yang sama. Potongan Laravel di bawah adalah ilustrasi untuk dibaca, belum dijalankan karena Laravel baru dipasang beberapa sub bab ke depan.

    Proyek siswa (PHP native), berkas public/tambah.php:

    $errors = $validator->validasi($data);

if ($errors === []) {
    $repository->simpan(new Siswa(0, $data["nim"], $data["nama"], $data["email"], $data["jurusan"]));
    header("Location: index.php?pesan=tambah");
    exit;
}

    Laravel (ilustrasi), berkas app/Http/Controllers/SiswaController.php:

    public function store(Request $request): RedirectResponse
{
    $validated = $request->validate([
        'nim' => ['required', 'digits_between:8,12', 'unique:siswa,nim'],
        'nama' => ['required', 'max:100'],
        'email' => ['required', 'email'],
    ]);

    Siswa::create($validated);

    return redirect()->route('siswa.index')->with('status', 'Siswa berhasil ditambahkan.');
}

    Dan satu baris pemetaan URL, berkas routes/web.php:

    Route::post('/siswa', [SiswaController::class, 'store']);

    Penjelasan Kode¶

    Bagian Laravel Padanan di versi native Penjelasan
    $request->validate([...]) SiswaValidator::validasi() Aturan ditulis sebagai daftar; jika gagal, pengguna otomatis dikembalikan ke form beserta pesan error dan isian lama
    'unique:siswa,nim' Pemeriksaan NIM unik di validator Aturan bawaan yang memeriksa database
    Siswa::create($validated) SiswaRepository::simpan() Eloquent menyimpan ke database tanpa kode berkas JSON
    redirect()->route(...)->with(...) header("Location: ...") dan exit Redirect plus pesan satu kali (flash message)
    Route::post('/siswa', [...]) Berkas tambah.php terpisah Satu baris menghubungkan URL ke method controller

    Kode Laravel jauh lebih pendek karena pekerjaan umum disediakan framework. Semua istilah di atas (controller, Eloquent, validation) akan dijelaskan satu per satu pada bab utama masing-masing; di sini cukup bandingkan bentuknya.

    Latihan dasar¶

    Latihan implementasi¶

    I1. Peta fitur - Masalah: kamu ingin tahu fitur Laravel yang menggantikan kode manual proyek siswa. - Persyaratan: lengkapi tabel catatan dengan minimal sepuluh baris, masing-masing dengan tautan ke halaman dokumentasi 13.x. - Perilaku yang diharapkan: semua tautan membuka halaman dengan 13.x pada alamat. - Tujuan belajar: menavigasi dokumentasi resmi.

    I2. Membaca kebijakan dukungan - Masalah: sebuah perusahaan masih memakai Laravel 12 dan bertanya apakah perlu pindah ke 13. - Persyaratan: berdasarkan tabel rilis, tulis tiga pertimbangan (versi PHP, batas perbaikan bug, batas perbaikan keamanan). - Perilaku yang diharapkan: jawabanmu merujuk pada tanggal di tabel resmi, bukan perkiraan. - Tujuan belajar: memahami siklus dukungan versi.

    Latihan tantangan¶

    T1. Pilih pola untuk tiga aplikasi - Masalah: tiga proyek: (a) sistem akademik berbasis web, (b) aplikasi mobile pemesanan makanan, (c) situs berita dengan halaman web biasa. - Persyaratan: tentukan untuk masing-masing apakah Laravel dipakai sebagai full stack atau API backend, lengkap dengan alasan dan dua fitur Laravel yang paling relevan. - Perilaku yang diharapkan: alasanmu konsisten dengan penjelasan dua pola dalam dokumentasi. - Tujuan belajar: menerapkan konsep pada skenario nyata. - Catatan: kerjakan mandiri; diskusikan dengan rekan atau mentor bila ada.

    Uji Pemahaman¶

    1. Apa yang dimaksud framework, dan mengapa berguna?
    2. Apa beda PHP dan Laravel?
    3. Sebutkan lima fitur Laravel dan padanan kode manualnya di proyek siswa.
    4. Apa beda full stack framework dan API backend?
    5. Versi PHP minimum untuk Laravel 13.x berapa?
    6. Berapa lama perbaikan bug dan perbaikan keamanan diberikan untuk setiap rilis Laravel?
    7. Mengapa memeriksa versi pada alamat dokumentasi itu penting?
    8. Sebutkan satu kelebihan dan satu batasan memakai Laravel.
    Kunci jawaban singkat
    1. Kerangka kerja berisi struktur dan alat siap pakai; menghemat pekerjaan berulang dan mengurangi kesalahan umum.
    2. PHP adalah bahasa; Laravel adalah framework yang ditulis dengan PHP.
    3. Contoh: routing (berkas per halaman), Blade (views/), validation (SiswaValidator), Eloquent (SiswaRepository), CSRF (belum ada).
    4. Full stack: Laravel membuat tampilan; API backend: Laravel menyediakan data untuk aplikasi lain.
    5. PHP 8.3.
    6. Bug 18 bulan, keamanan 2 tahun.
    7. Cara penulisan dapat berbeda antar versi.
    8. Kelebihan: hemat pekerjaan; batasan: ada kurva belajar.

    Ringkasan¶

    • Framework menyediakan struktur dan alat siap pakai; Laravel adalah framework PHP untuk aplikasi web.
    • Fitur Laravel menggantikan banyak pekerjaan manual: routing, tampilan, validasi, database, keamanan, dan lainnya.
    • Laravel dapat dipakai sebagai full stack framework atau API backend.
    • Materi ini memakai Laravel 13.x dengan PHP 8.3 atau lebih baru.
    • Dokumentasi resmi adalah sumber utama; selalu cek versinya.
